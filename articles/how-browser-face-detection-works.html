How Browser Face Detection Works: MediaPipe and BlazeFace

A few years ago, running a neural network on live video meant a powerful computer or a cloud server. Today a web page can find faces in your webcam feed many times per second, without installing anything and without sending a single frame off your device. Here is how that works, using the stack FaceVision is built on: Google's MediaPipe and the BlazeFace model.

The pieces

Browser face detection relies on three ingredients:

  1. A trained model: a small neural network, stored as a file, that has learned what faces look like.
  2. A runtime: code that can execute that model efficiently in a browser.
  3. Glue code: JavaScript that feeds images to the runtime and draws the results.

MediaPipe Tasks provides the runtime and a ready-made "Face Detector" task. BlazeFace is the model behind it.

BlazeFace: built for speed

BlazeFace was introduced by Google researchers in the 2019 paper "BlazeFace: Sub-millisecond Neural Face Detection on Mobile GPUs". The goal was a detector fast enough for real-time use on phones, as a first step for other face features.

A few design ideas make it fast:

  • Small input. The short-range version works on a small, downscaled image. Faces close to the camera, such as in a selfie or webcam, are still large enough at that size to detect.
  • Lightweight layers. The network is built from depthwise separable convolutions, which split one expensive operation into two cheap ones. This greatly reduces the arithmetic needed per image.
  • Anchors. Like other single-shot detectors, BlazeFace predicts results relative to a fixed grid of "anchor" boxes spread across the image. For each anchor, it outputs a score (how likely a face is there) and adjustments to turn the anchor into a tight box.
  • Keypoints. Alongside each box it predicts six facial keypoints: two eyes, two ear regions (tragions), the nose tip and the mouth centre.

Because neighbouring anchors often detect the same face, many overlapping boxes come out. A post-processing step merges or removes duplicates (a form of non-maximum suppression), leaving one box per face.

MediaPipe Tasks in the browser

MediaPipe's web library, @mediapipe/tasks-vision, ships its inference engine as WebAssembly (Wasm), a compact binary format browsers run at near-native speed. When a GPU is available, it can use WebGL to run the model's maths on the graphics card. If the GPU path fails, it can fall back to the CPU. FaceVision tries the GPU first and falls back to CPU automatically.

In practice, starting the detector looks like this:

  1. Load the Wasm files with FilesetResolver.forVisionTasks().
  2. Create a detector with FaceDetector.createFromOptions(), pointing to the model file and choosing a running mode: IMAGE for single photos or VIDEO for a stream.
  3. Call detect(image) or detectForVideo(video, timestamp).

Each call returns a list of detections, each with a bounding box, a confidence score and keypoints. Google's Face Detector documentation describes the options and output in detail.

From pixels to boxes

When you pass an image to the detector, roughly the following happens:

  1. Pre-processing. The image is resized to the model's input size and pixel values are normalised.
  2. Inference. The network runs once over the whole image and outputs scores and box offsets for every anchor.
  3. Decoding. Offsets are converted into actual box coordinates.
  4. Filtering. Boxes below the minimum confidence are dropped. FaceVision uses a threshold of 0.5.
  5. Suppression. Overlapping boxes for the same face are merged.
  6. Mapping back. Coordinates are converted to the original image size.

That last step catches out many beginners. The image you see on screen is often scaled differently from the image's real pixel size. To draw boxes in the right place, you need to convert from the image's intrinsic dimensions to its displayed dimensions. FaceVision does this explicitly, which is why its boxes line up even when the preview is resized.

Video: doing it many times a second

For live camera input, the app uses getUserMedia to get a video stream, then calls detectForVideo on each animation frame with a timestamp. The timestamp lets MediaPipe know frames are sequential. Because the model is small, this can keep up with the camera on many laptops and phones, though actual speed depends on your hardware and browser.

Limits to know about

  • The short-range model is tuned for faces fairly close to the camera. Small, distant faces in a group photo may be missed.
  • Strong side profiles, heavy occlusion (masks, hands) and very poor lighting reduce accuracy.
  • Confidence scores are not probabilities you can treat as exact; they are useful for ranking and thresholding.

Why it runs locally

The model file and library are downloaded once, then everything happens on your machine. Your photos never need to travel anywhere to be analysed. That combination of speed and privacy is what makes in-browser detection so appealing. Read more in our article on on-device AI and privacy.
